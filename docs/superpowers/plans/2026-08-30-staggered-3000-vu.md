# Staggered 3,000 VU Load Test Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement and run a 3,000-VU, one-request-per-VU scenario whose requests begin evenly across 60 seconds and whose stability contract includes zero request, Hikari, and MySQL connection failures.

**Architecture:** Extend the existing k6 profile library with a `vu-3000-minute` per-VU scenario and a pure, Node-testable delay function. Keep the application synchronous and unchanged. Extend the result validator so a passing run proves the exact VU/request count and connection-safety claims.

**Tech Stack:** k6, Node.js test runner, Bash, Spring Boot Actuator, HikariCP, Tomcat, MySQL 8.

## Global Constraints

- 3,000 VUs each execute exactly one iteration.
- Request starts are spread uniformly over 60 seconds.
- Existing/new mix remains 60/40 and Mock RAG remains 5,000–10,000ms.
- The request deadline is 120 seconds and scenario maximum duration is 180 seconds.
- A passing result requires 3,000 successes, zero failures, zero drops, zero Hikari acquisition timeouts, and zero MySQL max-connection errors.
